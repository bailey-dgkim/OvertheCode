# 콘텐츠를 데이터로, 그리고 만든 걸 내가 겪다

> 2026-07-24 · OvertheCode 개발일지

케이스 1개로 형식을 확인한 뒤, 이번엔 **콘텐츠를 대량으로 찍어내는 방법**과 **완전히 새로운 학습 방식**을 만들었다.

## 1. 콘텐츠를 코드에서 떼어내 JSON으로

케이스를 컴포넌트 안에 박아넣을 수도 있었다. 대신 내용은 JSON, 그리는 건 렌더러 하나로 나눴다.

```
JSON 10개 (내용만 다름)  →  렌더러 1벌 (다 그림)
```

이유는 세 가지였다.
- **케이스 추가가 싸다** — 새 케이스 = JSON 파일 하나
- **나중에 백엔드로 옮기기 쉽다** — JSON은 순수 데이터라 Java도 읽는다. 콘텐츠를 두 번 쓸 일이 없다
- **검증할 수 있다** — 정해진 모양이라 기계가 검사한다

그리고 이 결정이 **같은 세션 안에서 바로 보상받았다.** 데이터만 쓰면 되니 운영 케이스 9개를 배치로 빠르게 채울 수 있었다.

## 2. lint가 못 잡는 걸 잡는 검증기

케이스를 손으로 쓰다 보면 실수가 난다. 특히 이건 무섭다.

> 정답이 선택지에 없음 → 학습자가 **영원히 다음으로 못 넘어가는데**, 화면은 멀쩡해 보인다.

`npm run validate:cases` 스크립트를 만들어 이런 걸 1초 만에 잡게 했다. 일부러 망가뜨린 케이스로 7건이 다 걸리는 것도 확인했다. **lint 통과 = 문법이 맞다**이지 **필요한 게 다 있다**는 뜻이 아니다. 도구의 한계를 아는 게 중요하다.

## 3. 직접 고쳐보다가 죽은 코드를 만났다

기능 하나(트랙 선택에서 뒤로가기 버튼)를 내가 직접 구현했다. 그 과정에서:

- **에러 메시지는 답을 알려준다** — `107:9 already been declared`. 줄 번호부터 열어보면 된다
- 이름 충돌, props 전달 누락 같은 흔한 실수를 직접 겪었다

그리고 온보딩 화면을 지우다가, **아무도 안 쓰는데 남아있는 코드**를 만들었다. `lint`는 이걸 못 잡았다. 훅에서 반환은 되고 있어서, 아무도 안 꺼내 쓴다는 건 다른 파일을 봐야 알 수 있으니까.

이게 바로 실무 레거시에 쓰레기 코드가 쌓이는 방식이다. 지웠다가 뭔가 마비되면 책임이 오니까, 그냥 둔 채로 10년이 지난다. **안 지워도 아무 일이 안 일어나기 때문에** 계속 쌓인다.

## 4. 객관식을 넘어 — 코드를 직접 클릭하기

바이브 코딩하는 사람들의 진짜 고민은 이거다.

> "화면은 보이는데, 이게 코드 **어디**에 있는지를 모른다."

그래서 새 학습 유형을 만들었다. 객관식이 아니다. **진짜 코드를 보여주고, 그 위에서 직접 정답 위치를 클릭**한다.

- 1단계: 파일 트리에서 고칠 파일 찾기 (오답 파일도 "왜 아닌지" 알려준다)
- 2단계: 코드가 열리고, 줄 사이 빈틈에서 넣을 자리를 클릭

`OrderForm.jsx`의 실제 코드 26줄을 띄우고, "차량 모델과 계약 금액 사이"를 코드에서 찾게 한다. 핵심 메시지는 하나다 — **화면에 보이는 모든 것은 코드 어딘가에 적혀 있다.**

## 방향이 잡혔다

학습 트랙을 4개로 정리했다.

- **개발** — 없던 걸 만든다
- **운영** — 터진 걸 고친다
- **개선** — 이미 있는 걸 안전하게 바꾼다 ← 이번에 시작
- **AI 협업** — AI가 만든 코드를 검증한다

만든 걸 내가 직접 겪으면서, 무엇을 가르쳐야 하는지가 더 선명해졌다. 죽은 코드도, 코드 길찾기도, 전부 이번 세션에 내가 실제로 부딪힌 것들이다.
